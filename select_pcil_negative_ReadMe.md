# PCIL (-) Selection

`select_pcil_negative()` identifies **PCIL (-)** lines to serve as genetically similar controls for PCIL (+) lines.

For each genomic target, the function first identifies all PCIL lines carrying an introgression that fully spans the target. These lines define the complete PCIL (+) carrier population for that region.

PCIL (-) candidates are then defined as PCIL lines that **do not carry an introgression spanning the target**.

The function subsequently attempts to identify the most appropriate PCIL (-) match for each PCIL (+) by:

1. preferentially searching within the same PCIL family,
2. identifying genetically similar candidates using IBS distance,
3. refining those candidates using genome-wide introgression recovery and inbreeding coefficient (`F`).

---

## What is a PCIL (-)?

For this pipeline, a **PCIL (-)** is a PCIL line that does **not** contain an introgression block fully spanning the target region.

For a target defined as:

PCIL (+):
```text
Introgression block
|---------------------------------------|
                 Target
              |----------|
```
PCIL (-):
```text
Introgression block
|-------------|
                 Target
              |----------|
```

The PCIL (-) candidate population is therefore defined as:

```text
Complete PCIL population
          -
All PCIL (+) carriers
          =
PCIL (-) candidates
```

Importantly, the function determines the complete PCIL (+) carrier population from the full introgression dataset before applying any population filters to the PCIL (-) candidates.
This prevents a true carrier from being incorrectly classified as PCIL (-) simply because that line was excluded by an availability or experimental filter.

---

## Running `select_pcil_negative()`

### Minimum requirements

At minimum, `select_pcil_negative()` requires two arguments:

| Argument | Description |
| --- | --- |
| `pcil_data` | PCIL genomic data object generated by `load_pcil_data()`. |
| `regions` | Standardized genomic target(s) to evaluate, containing `Region`, `Chr`, `Start`, and `End`. |

A minimal call is:

```r
pcil_negatives <- select_pcil_negative(
  pcil_data = pcil_data,
  regions = pcil_positives$regions
)
```

With only these arguments, the function:

1. identifies all PCIL (+) carriers for each target,
2. defines all non-carriers as potential PCIL (-),
3. matches **one best PCIL (-)** to each PCIL (+).

The `regions` object can be obtained directly from the output of:

```r
select_pcil_positive()
```
---

# 1. Define the genomic targets

## `pcil_data`

`pcil_data` contains the PCIL genomic datasets required by the function and is generated using:

```r
pcil_data <- load_pcil_data()
```

The primary datasets used by `select_pcil_negative()` are:

- `introgressions`
- `metadata`
- `IBS_dis`
- `genomewide_introgressions`
- `inbreeding_coefficient`
---

## `regions`

`regions` defines the genomic target or targets for which PCIL (+)/PCIL (-) comparisons will be generated.

The input must contain:

| Column | Description |
| --- | --- |
| `Region` | Unique identifier for the genomic target. |
| `Chr` | Chromosome containing the target. |
| `Start` | Start coordinate of the target interval in base pairs. |
| `End` | End coordinate of the target interval in base pairs. |

This ensures that PCIL (+) and PCIL (-) selection use exactly the same genomic target coordinates.

---

# 2. Identification of the PCIL (-) candidate population

Before selecting a PCIL (-), the function determines which lines are true PCIL (+) carriers for each target.
This step is performed separately for every target.

Conceptually:

```text
Complete PCIL population
          ↓
Does line carry an introgression
fully spanning the target?
       ↙          ↘
     YES          NO
      ↓            ↓
 PCIL (+)     PCIL (-)
              candidate
```

This definition occurs **before optional population filters are applied**.

---

# 3. Optional population filtering

Population filtering is **not required** to identify PCIL (-).

By default, every valid non-carrier in the PCIL population can enter the PCIL (-) candidate pool.

Two arguments can optionally restrict the negative candidate population:

```text
global_available_ids
available_ids
```

These filters are applied **only to PCIL (-) candidates**.

They do not alter which lines are considered PCIL (+) at this stage.

---

## `global_available_ids`

`global_available_ids` is a vector of SampleIDs allowed to serve as PCIL (-) candidates.

For example:

```r
global_available_ids <- c(
  "Sample_1",
  "Sample_2",
  "Sample_3"
)
```

This filter is applied across **all targets**.

Only non-carriers present in `samples_to_keep` can be considered as PCIL (-) matches.

This can be useful for operational or experimental restrictions such as:

- seed availability,
- phenotype availability,
- experimental availability,
- generation,
- breeding background,
- or another user-defined criterion.

When selecting material for an experiment, `global_available_ids` can be used to restrict PCIL (-) candidates to lines with sufficient seed availability.

If:

```r
global_available_ids = NULL
```

no global restriction is applied to the negative candidate population.

---

## `available_ids`

`available_ids` provides a **target-specific population filter** for PCIL (-) candidates.

Unlike `global_available_ids`, which applies the same SampleID list across all targets, `available_ids` allows a different candidate population for each target.

The input must contain:

| Column | Description |
| --- | --- |
| `sample_id` | SampleID allowed to serve as a PCIL (-) candidate. |
| `selection` | Target/Region for which the SampleID is allowed. |

For example:

```text
sample_id     selection
Sample_1      Variant_A
Sample_2      Variant_A
Sample_3      Variant_B
Sample_4      Variant_B
```

For `Variant_A`, only non-carriers among:

```text
Sample_1
Sample_2
```

would be considered.

For `Variant_B`, only non-carriers among:

```text
Sample_3
Sample_4
```

would be considered.

One use of `available_ids` is to restrict negative selection to families or samples associated with a particular target.

For example:

```r
available_ids <- pcil_families$pcil_summary[
  c("sample_id", "selection")
]
```

If:

```r
available_ids = NULL
```

no target-specific restriction is applied.

---

## Combining population filters

`global_available_ids` and `available_ids` can be used together.

When both are supplied, the global restriction is applied first, followed by the target-specific restriction.

Conceptually:

```text
All true non-carriers
          ↓
global_available_ids
          ↓
Global negative subset
          ↓
available_ids
          ↓
Target-specific negative subset
          ↓
PCIL (-) matching
```

For example, `global_available_ids` could restrict all negative candidates to lines with sufficient seed, while `available_ids` could impose an additional target-specific restriction.

---

# 4. Select which PCIL (+) lines to match

By default:

```r
pcil_positive_df = NULL
```

When `pcil_positive_df` is `NULL`, the function generates a PCIL (-) match for **every PCIL (+) carrier** identified for each region.

Conceptually:

```text
All PCIL (+)
      ↓
Find PCIL (-)
for each carrier
```

The user can instead provide a selected subset of PCIL (+) lines.

For example:

```r
pcil_positive_df = pcil_positives$best_lines
```

This is particularly useful after running:

```r
select_pcil_positive(sel = N)
```

because the function will then identify negative controls only for the preferred PCIL (+) lines.

For example:

```r
pcil_negatives <- select_pcil_negative(
  pcil_data = pcil_data,
  regions = pcil_positives$regions,
  pcil_positive_df = pcil_positives$best_lines
)
```

Conceptually:

```text
All PCIL (+)
      ↓
select_pcil_positive(sel = N)
      ↓
Best PCIL (+)
      ↓
pcil_positive_df
      ↓
Find PCIL (-) only
for selected positives
```

`pcil_positive_df` must contain at least:

```text
SampleID
Region
```

so that the function can identify which PCIL (+) lines should be processed for each target.

---

# 5. PCIL (-) matching logic

PCIL (-) selection occurs independently for each PCIL (+).

The objective is not simply to identify any non-carrier.

Instead, the function attempts to identify a PCIL (-) that:

```text
Does not carry the target introgression
               +
Shares the closest possible genetic background
               +
Has strong recurrent-parent genome recovery
               +
Is relatively highly inbred
```

The matching procedure occurs in multiple steps.

---

## 1) Prefer same-family PCIL (-)

For each focal PCIL (+), the function identifies its PCIL family using:

```r
pcil_data$metadata
```

It then determines whether any valid PCIL (-) candidates belong to that same family.

If same-family candidates are available:

```text
PCIL (+)
   ↓
Same-family PCIL (-) candidates available?
   ↓
YES
   ↓
Use only same-family candidates
```

If no same-family candidates are available:

```text
PCIL (+)
   ↓
Same-family PCIL (-) candidates available?
   ↓
NO
   ↓
Use broader valid PCIL (-) population
```

The family criterion is therefore a **soft filter**.

Same-family PCIL (-) lines are preferred, but the analysis does not fail when a same-family negative is unavailable.

This approach prioritizes more closely controlled genetic comparisons while still allowing a match to be identified when family-level material is limited.

---

## 2) Genetic similarity using IBS distance

After the PCIL (-) candidate population has been defined, the function uses pairwise IBS distance to identify candidates most genetically similar to the focal PCIL (+).

IBS distance represents:

```text
1 - IBS
```

Therefore:

```text
lower IBS distance = greater genome-wide genetic similarity
```

For each PCIL (+), the function retrieves IBS distances only for the valid negative candidates remaining after:

1. non-carrier definition,
2. optional population filtering,
3. same-family preference.

Candidates lacking an IBS value are removed.

---

## 3) IBS candidate preselection

The number of IBS candidates passed to genome-quality refinement depends on `n_neg`.

When:

```r
n_neg = NULL
```

or:

```r
n_neg = 1
```

the function retains up to the **three closest PCIL (-) candidates by IBS distance**.

Conceptually:

```text
Valid PCIL (-) candidates
          ↓
Rank by IBS distance
          ↓
3 closest candidates
          ↓
Genome-quality refinement
          ↓
1 best PCIL (-)
```

This allows the final negative to be selected using genome-quality information rather than automatically choosing the single closest IBS match.

When multiple negatives are requested using:

```r
n_neg > 1
```

the function retains up to `n_neg` closest IBS candidates for genome-quality refinement.

For example:

```r
n_neg = 4
```

passes up to four closest IBS candidates into the next selection step.

---

## 4) Genome-quality refinement

After IBS preselection, the remaining candidates are ranked in the following order:

```text
1. Lowest total_Mb
2. Fewest total_blocks
3. Highest F
```

### `total_Mb`

Total amount of donor-derived genome remaining in the PCIL (-).

Lower values are preferred.

### `total_blocks`

Total number of donor introgression blocks across the genome.

Lower values are preferred.

### `F`

Genome-wide inbreeding coefficient.

Higher values are preferred.

The matching strategy can therefore be summarized as:

```text
Valid PCIL (-) candidates
          ↓
Prefer same family
          ↓
Closest IBS candidates
          ↓
Lowest total_Mb
          ↓
Fewest total_blocks
          ↓
Highest F
          ↓
Best PCIL (-)
```

Importantly, IBS and genome-quality metrics have different roles.

IBS determines the **genetically closest candidate set**.

Genome-wide introgression recovery and `F` then determine the preferred line **within that candidate set**.

---

# 6. Selecting one or multiple PCIL (-) matches

The argument:

```r
n_neg
```

controls whether only the best negative or an extended set of negative candidates is returned.

The default is:

```r
n_neg = NULL
```

With `NULL` or:

```r
n_neg = 1
```

the function returns one best PCIL (-) per PCIL (+).

---

## Multiple PCIL (-) candidates

To return several candidate negatives for each PCIL (+), provide:

```r
n_neg > 1
```
This will return the number requested  of PCIL (-) candidates per PCIL (+).

Each retained candidate receives:

```text
Pair_Rank
```

where:

```text
Pair_Rank = 1
```

represents the highest-ranked PCIL (-) within the refined candidate set.

If fewer than `n_neg` valid candidates are available, all remaining candidates are returned.

---

## Function arguments at a glance

| Argument | Default | Role |
| --- | --- | --- |
| `pcil_data` | — | **Required.** PCIL genomic data object. |
| `regions` | — | **Required.** Standardized target regions containing `Region`, `Chr`, `Start`, and `End`. |
| `pcil_positive_df` | `NULL` | Optional subset of PCIL (+) lines to match. If `NULL`, all PCIL (+) carriers are processed. |
| `n_neg` | `NULL` | Number of PCIL (-) candidates requested per PCIL (+). `NULL` or `1` returns one best match. |
| `global_available_ids` | `NULL` | Optional global restriction applied only to PCIL (-) candidates. |
| `available_ids` | `NULL` | Optional target-specific restriction applied only to PCIL (-) candidates. |

---

# 7. Output

The output depends on `n_neg`.

## One PCIL (-) per PCIL (+)

If:

```r
n_neg = NULL or n_neg=1
```

the function returns:

```text
pcil_negatives
│
└── pairs_best
```

---

## Multiple PCIL (-) candidates per PCIL (+)

If:

```r
n_neg > 1
```

the function returns:

```text
pcil_negatives
│
├── pairs_best
└── pairs_extended
```

`pairs_best` is always generated.

`pairs_extended` is generated only when multiple negatives are requested.

---

## `pairs_best`

Contains the highest-ranked PCIL (-) match for each PCIL (+).

Each row represents one PCIL (+)/PCIL (-) pair.

| Column | Description |
| --- | --- |
| `SampleID_Positive` | SampleID of the focal PCIL (+). |
| `SampleID_Negative` | SampleID of the selected PCIL (-). |
| `Region` | Genomic target used to define PCIL (+) and PCIL (-). |
| `Chr` | Chromosome containing the target. |
| `Start` | Start coordinate of the target interval in base pairs. |
| `End` | End coordinate of the target interval in base pairs. |
| `IBS_dis` | Pairwise IBS distance between the PCIL (+) and selected PCIL (-). Lower values indicate greater genetic similarity. |
| `total_Mb_neg` | Total amount of donor-derived genome in the selected PCIL (-), in Mb. |
| `total_blocks_neg` | Total number of donor introgression blocks in the selected PCIL (-). |
| `F_neg` | Genome-wide inbreeding coefficient of the selected PCIL (-). |
| `Family` | Family of the focal PCIL (+) used during the same-family matching step. |

The `Family` column records the family associated with the focal PCIL (+). When same-family PCIL (-) candidates are available, they are preferentially selected from this family. If no same-family candidate exists, the selected PCIL (-) may come from the broader candidate population.

---

## `pairs_extended`

`pairs_extended` is returned only when:

```r
n_neg > 1
```

It contains the ranked set of PCIL (-) candidates retained for each PCIL (+).

| Column | Description |
| --- | --- |
| `SampleID_Positive` | SampleID of the focal PCIL (+). |
| `SampleID_Negative` | SampleID of the candidate PCIL (-). |
| `Region` | Genomic target associated with the pair. |
| `Chr` | Chromosome containing the target. |
| `Start` | Start coordinate of the target interval in base pairs. |
| `End` | End coordinate of the target interval in base pairs. |
| `IBS_dis` | Pairwise IBS distance between the PCIL (+) and PCIL (-). |
| `total_Mb_neg` | Total amount of donor-derived genome in the PCIL (-), in Mb. |
| `total_blocks_neg` | Total number of donor introgression blocks in the PCIL (-). |
| `F_neg` | Genome-wide inbreeding coefficient of the PCIL (-). |
| `Family` | Family of the focal PCIL (+) used during the same-family matching step. |
| `Pair_Rank` | Final ranking of the PCIL (-) candidate within the refined candidate set. |

`Pair_Rank = 1` corresponds to the same PCIL (-) reported in `pairs_best`.

The extended output is useful when the user wants multiple genetically appropriate controls or wants to consider additional experimental information before choosing the final PCIL (-).

---

# 8. Relationship to `select_pcil_positive()`

`select_pcil_negative()` uses the same standardized genomic regions used during PCIL (+) selection. It can be run independently as long as the "region" is generated
in the same way as required by `select_pcil_positive`. 

The `select_pcil_negative` should be restricted by `available_ids` or `global_available_ids` in the same way than `select_pcil_postive`/
