# PCIL (+) Selection

`select_pcil_positive()` identifies **PCIL (+)** lines carrying donor-derived introgression blocks that fully span a user-defined genomic target.

---
## What is a PCIL (+)?

For this pipeline, a **PCIL (+)** is a PCIL line containing a donor-derived introgression block that fully spans the genomic target being evaluated.
An introgression is considered to contain the target when:

```text
block_start_bp <= Start AND block_end_bp >= End
```

Conceptually:
PCIL (+)
```text
Introgression block
|---------------------------------------|
                 Target
              |----------|
```
PCIL (-)
```text
Introgression block
|-------------|
                 Target
              |----------|
```
The introgression must therefore cover the **entire target interval**, rather than simply overlap part of it.
---

The `select_pcil_positive()`function can be used independently with three types of genomic targets:

- a **gene**,
- a **genomic position** such as a SNP or INDEL,
- or a **user-defined genomic region**.
---

The basic workflow can be expanded is:
```text
Define genomic target
        ↓
Optional population filtering
        ↓
Identify PCIL (+)
        ↓
Optional selection and ranking
        ↓
Best PCIL (+)
```

---
## Running `select_pcil_positive()`

### Minimum requirements
At minimum, `select_pcil_positive()` requires three arguments:

| Argument | Description |
| --- | --- |
| `pcil_data` | PCIL genomic data object generated by `load_pcil_data()`. |
| `input` | Genomic target or targets to evaluate. |
| `type` | Defines how `input` is interpreted: `"gene"`, `"region"`, or `"position"`. |

A minimal call is:

```r
pcil_positives <- select_pcil_positive(
  pcil_data = pcil_data,
  input = input,
  type = "position"
)
```

With only these arguments, the function identifies **all PCIL (+) lines** containing an introgression that fully spans the target.


# 1. Define the genomic target

## `pcil_data`

`pcil_data` contains the PCIL genomic datasets required by the function and is generated using:

```r
pcil_data <- load_pcil_data()
```

The primary datasets used by `select_pcil_positive()` are:

- `introgressions`
- `genomewide_introgressions`
- `inbreeding_coefficient`
- `gene_regions`

[View `load_pcil_data()` documentation](https://github.com/claracruet/PCIL_selection_pipeline/blob/main/load_pcil_data_ReadMe.md)

---

## `input`

`input` defines the genomic target or targets to evaluate.

The required format depends on the value supplied to `type`.

Multiple targets can be evaluated simultaneously.

---


## `type`

`type` defines how `input` should be interpreted.

Three input types are supported:

```text
gene
region
position
```

All three input types are internally converted to the same standardized format:

```text
Region | Chr | Start | End
```

---

## Input type: `gene`

Use:

```r
type = "gene"
```

when the target is one or more genes.

The input can be a single gene ID:

```r
input <- "Sobic.003G260300"
```

a character vector:

```r
input <- c(
  "Sobic.003G260300",
  "Sobic.005G213600"
)
```

or a data frame containing a `Region` column:

```text
Region
Sobic.003G260300
Sobic.005G213600
```

Gene IDs are matched against:

```r
pcil_data$gene_regions
```
If a requested gene is not found in the v5.1 annotation, the function reports that the gene was not found and should be verified.

---

## Input type: `position`

Use:

```r
type = "position"
```

when the target is a specific genomic position, such as a SNP or INDEL.

The input must contain:

| Column | Description |
| --- | --- |
| `Region` | Identifier assigned to the target. This can be a variant ID or another unique label. |
| `Chr` | Chromosome containing the target position. |
| `pos` | Genomic coordinate of the target in base pairs. |

For example:

```r
input_pcil <- data.frame(
  Region = "INDEL_Chr03_66131272",
  Chr = "Chr03",
  pos = 66131272
)
```

Because introgressions are represented as genomic blocks rather than individual bases, the position is expanded using the `window` argument.

For example:

```r
window = 1000
```

produces:

```text
Start = pos - 1000
End   = pos + 1000
```

The resulting standardized region is therefore:

```text
Region                  Chr      Start       End
INDEL_Chr03_66131272    Chr03    66130272    66132272
```

`window` defines the number of bp added upstream and downstream of the target and is used only for position-based targets.

---

## Input type: `region`

Use:

```r
type = "region"
```

The input must contain:

| Column | Description |
| --- | --- |
| `Region` | Unique name or identifier for the genomic target. |
| `Chr` | Chromosome containing the target region. |
| `Start` | Start coordinate of the target region in base pairs. |
| `End` | End coordinate of the target region in base pairs. |

For example:

```r
input_region <- data.frame(
  Region = "Target_region_1",
  Chr = "Chr03",
  Start = 65000000,
  End = 67000000
)
```

No coordinate conversion is required for this input type.

---

# 2. Optional population filtering

Population filtering is **not required** to identify PCIL (+). The goal of this filtering is to restrict the population for a specific hypothesis or for operational considerations such as phenotype or seed availability. By default, the PCIL (+) selection is applied at the genomic level and therefore there can be samples
for which we currently do not have seed availability.

By default, `select_pcil_positive()` searches the complete PCIL introgression population contained in:

```r
pcil_data$introgressions
```

Two arguments can optionally restrict the population searched:

```text
global_available_ids
available_ids
```

These filters are applied **before PCIL (+) identification** and are independent of `sel`.
Therefore, population filtering can be used even when the user only wants to identify PCIL (+) lines and does not want to perform the subsequent 
selection and ranking procedure.

Conceptually:

```text
Complete PCIL population (at the genomic level)
          ↓
Optional population filters
          ↓
Population searched
          ↓
Identify PCIL (+)
```

---

## `global_available_ids`

`global_available_ids` is a vector of SampleIDs that are allowed to enter the analysis.

For example:

```r
global_available_ids <- c(
  "Sample_1",
  "Sample_2",
  "Sample_3"
)
```

This filter is applied across **all targets** being evaluated. This means that the PCIL positives will be found only among the supplied samples. For experiments requiring seed, `global_available_ids` should generally be used to restrict selection to lines with sufficient seed availability.

Examples of scenarios someone would like to restrict the PCIL (+) selection include:

- seed availability,
- phenotype,
- experimental availability,
- a specific family or breeding background,
- generation,
- or another user-defined criterion.

For example:

```r
pcil_positives <- select_pcil_positive(
  pcil_data = pcil_data,
  input = input_pcil,
  type = "position",
  global_available_ids = samples_to_keep
)
```
---

## `available_ids`

`available_ids` provides a **target-specific population filter**.

Unlike `global_available_ids`, which applies the same SampleID list to every target, `available_ids` allows a different set of PCIL lines to be used for each target.

The input must contain:

| Column | Description |
| --- | --- |
| `sample_id` | SampleID allowed to enter the analysis. |
| `selection` | Target/Region for which that SampleID should be considered. |

For example:

```text
sample_id     selection
Sample_1      Variant_A
Sample_2      Variant_A
Sample_3      Variant_B
Sample_4      Variant_B
```

For `Variant_A`, only:

```text
Sample_1
Sample_2
```

would be searched.

For `Variant_B`, only:

```text
Sample_3
Sample_4
```

would be searched.

Conceptually:

```text
Target A
   ↓
Samples allowed for A
   ↓
PCIL (+) search

Target B
   ↓
Samples allowed for B
   ↓
PCIL (+) search
```

One use of this argument is to supply the output of:

```r
select_pcil_families_by_variant()
```

For example:

```r
available_ids <- pcil_families$pcil_summary[
  c("sample_id", "selection")
]
```

This restricts each variant to PCIL families expected to segregate for that variant.

However, **`select_pcil_families_by_variant()` is not required to run `select_pcil_positive()`**.

`available_ids` can come from any appropriate target-specific sample list.

If:

```r
available_ids = NULL
```

no target-specific population restriction is applied.

---

## Combining population filters

`global_available_ids` and `available_ids` can be used together.

When both are supplied, the global filter is applied first, followed by the target-specific filter.
---

# 3. Identification of PCIL (+)

For each standardized target region, the function starts from the complete PCIL introgression dataset and applies any optional population filters.

The introgression dataset is then restricted to the chromosome containing the target.

The function identifies introgression blocks satisfying:

```text
block_start_bp <= target Start AND block_end_bp >= target End
```

Only blocks that fully span the target are retained.

For each identified PCIL (+), the function records:

| Column | Description |
| --- | --- |
| `SampleID` | Unique identifier of the PCIL (+) line. |
| `Region` | Target identifier being evaluated. |
| `Chr` | Chromosome containing the target. |
| `Start` | Start coordinate of the target interval in base pairs. |
| `End` | End coordinate of the target interval in base pairs. |
| `ChrLabel` | Chromosome containing the introgression block. |
| `block_start_bp` | Start coordinate of the introgression block in base pairs. |
| `block_end_bp` | End coordinate of the introgression block in base pairs. |
| `block_len_Mb` | Length of the target-containing introgression block in Mb. |
| `mean_donor_frac` | Mean donor fraction across the target-containing introgression block. |
| `total_blocks` | Total number of donor introgression blocks detected across the PCIL genome. |
| `total_Mb` | Total genomic length represented by donor introgressions across the PCIL genome. |


The resulting dataset represents all PCIL (+) carriers identified **within the population searched during that run**.
If no PCIL (+) is identified for a particular target, the function reports a warning and continues evaluating the remaining targets.

---

# 4. Optional selection of preferred PCIL (+)

After PCIL (+) lines have been identified, the function can optionally perform an additional filtering and ranking procedure to select preferred experimental lines.

This procedure is activated using:

```r
sel
```

The default is:

```r
sel = NULL
```

Therefore, **selection is not performed by default**.
Selection is performed **independently for each target**.

When `sel` is provided, three selection parameters are used:

| Argument | Default | Description |
| --- | --- | --- |
| `donor_thresh` | `0.75` | Minimum mean donor fraction required during preferred PCIL (+) selection. |
| `block_quantile` | `0.75` | Quantile used to remove lines with the largest target-containing introgression blocks. |
| `F_quantile` | `0.25` | Quantile used to remove the least-inbred candidate lines. |

These three parameters are **only used when `sel` is provided**.
The default values are automatically used. The user only needs to specify them when different selection criteria are desired.

For example:

```r
pcil_positives <- select_pcil_positive(
  pcil_data = pcil_data,
  input = input,
  type = "position",
  sel = 5
)
```

uses:

```r
donor_thresh = 0.75
block_quantile = 0.75
F_quantile = 0.25
```

automatically.

---
## Logic for PCIL (+) selection

### 1) Donor fraction filter, is the first applied by using the `donor_thresh`

PCIL (+) lines are retained when:

```text
mean_donor_frac >= donor_thresh
```

`mean_donor_frac` represents the mean donor signal across the introgression block containing the target.

This ensures that the target-containing introgression has sufficient donor signal before the line is considered for the recommended subset.

---

### 2) Target introgression size filter

When more than five candidate lines remain after `donor_thresh` filtering, the function calculates the `block_len_Mb` quantiles for the target introgression.
and retains lines at or below that threshold.

With the default:

```text
block_quantile = 0.75
```

the largest approximately 25% of target-containing introgression blocks are removed.
---

### 3) Inbreeding coefficient filter

When more than five candidates remain, the function calculates the selected quantile of the inbreeding coefficient `F` and retains lines at or above that threshold.

With the default:

```text
F_quantile = 0.25
```

the least-inbred approximately 25% of the remaining candidates are removed.

Higher `F` values are preferred because they indicate greater homozygosity relative to expectation.
This filter is only applied when **more than five candidates** remain at this stage.

---

## 4) Genome-wide ranking

After filtering, the remaining PCIL (+) lines are ranked using three genome-wide criteria.

The ranking order is:

```text
1. Lowest total_Mb
2. Fewest total_blocks
3. Highest F
```

### `total_Mb`

Total amount of donor-derived genome remaining in the PCIL line.

Lower values are preferred.

### `total_blocks`

Total number of donor introgression blocks across the genome.

Lower values are preferred.

### `F`

Genome-wide inbreeding coefficient.

Higher values are preferred.

Conceptually, the ranking favors a PCIL (+) that:

```text
Carries the target introgression
           +
Has strong donor signal
           +
Has a relatively small target block
           +
Has less donor genome elsewhere
           +
Has fewer residual donor blocks
           +
Is more highly inbred
```

---

## 5) Select the top lines

After ranking, the function retains up to `sel` lines for each target.

For example:

```r
sel = 5
```

returns up to five selected PCIL (+) lines per target.

If fewer than five lines remain, all remaining lines are returned.

Each selected line receives a:

```text
Rank
```

where:

```text
Rank = 1
```

represents the highest-ranked PCIL (+) for that target.

---

## Selection workflow

The complete optional selection procedure is:

```text
All identified PCIL (+)
          ↓
mean_donor_frac >= donor_thresh
          ↓
If >5 lines:
remove largest target blocks
using block_quantile
          ↓
Add inbreeding coefficient (F)
          ↓
If >5 lines:
remove lowest F values
using F_quantile
          ↓
Rank remaining lines:
1. lowest total_Mb
2. fewest total_blocks
3. highest F
          ↓
Retain top sel lines
          ↓
best_lines
```

---

# 5. Output

The output depends on whether `sel` is provided.

## Without selection

If:

```r
sel = NULL
```

the function returns:

```text
pcil_positives
│
├── pcil_positive
└── regions
```

## With selection

If:

```r
sel = 5
```
[View `select_pcil_positive()`](https://gist.githubusercontent.com/claracruet/189e3a4a2aabf0527ef0845832597439/raw/select_pcil_positive.R)

the function returns:

```text
pcil_positives
│
├── pcil_positive
├── best_lines
└── regions
```

---

## `regions`

Contains the standardized genomic targets used during PCIL (+) identification.

Regardless of the original input type, the output has the format:

| Column | Description |
| --- | --- |
| `Region` | Identifier for the genomic target. |
| `Chr` | Chromosome containing the target. |
| `Start` | Start coordinate of the target interval in base pairs. |
| `End` | End coordinate of the target interval in base pairs. |

This object preserves the exact genomic intervals used to determine PCIL (+) status and is also used by downstream plotting and PCIL (−) selection functions.

---

## `pcil_positive`

Contains **all PCIL (+) lines identified for each target within the population searched during that run**.

Each row represents a PCIL line with an introgression block fully spanning the target region.

| Column | Description |
| --- | --- |
| `SampleID` | Unique identifier of the PCIL (+) line. |
| `Region` | Target for which the line was identified as PCIL (+). |
| `Chr` | Chromosome containing the target. |
| `Start` | Start coordinate of the target interval. |
| `End` | End coordinate of the target interval. |
| `ChrLabel` | Chromosome containing the introgression block. |
| `block_start_bp` | Start coordinate of the target-containing introgression. |
| `block_end_bp` | End coordinate of the target-containing introgression. |
| `block_len_Mb` | Length of the target-containing introgression in Mb. |
| `mean_donor_frac` | Mean donor fraction of the target-containing introgression. |
| `total_blocks` | Total number of donor introgression blocks across the genome. |
| `total_Mb` | Total amount of donor-derived genome across the genome, in Mb. |

`pcil_positive` is generated regardless of whether `sel` is used.

---

## `best_lines`

`best_lines` is returned only when `sel` is not `NULL`.

It contains the subset of PCIL (+) lines retained after the optional filtering and ranking procedure.
The table contains the PCIL (+) information described above, with additional inbreeding and ranking information.

| Column | Description |
| --- | --- |
| `SampleID` | Unique identifier of the selected PCIL (+) line. |
| `Region` | Target associated with the selected line. |
| `Chr` | Chromosome containing the target. |
| `Start` | Start coordinate of the target. |
| `End` | End coordinate of the target. |
| `ChrLabel` | Chromosome containing the target introgression block. |
| `block_start_bp` | Start coordinate of the target-containing introgression. |
| `block_end_bp` | End coordinate of the target-containing introgression. |
| `block_len_Mb` | Length of the target-containing introgression. |
| `mean_donor_frac` | Mean donor fraction across the target-containing introgression. |
| `total_blocks` | Total number of donor introgressions across the genome. |
| `total_Mb` | Total amount of donor-derived genome across the genome. |
| `F` | Genome-wide inbreeding coefficient. |
| `Rank` | Final PCIL (+) ranking within the target region. Rank 1 represents the highest-ranked line. |

The number of rows returned per target is limited by `sel`, but fewer lines may be returned when fewer candidates pass the filters.

---

# 6. Relationship to `select_pcil_families_by_variant()`

`select_pcil_positive()` is **independent of** `select_pcil_families_by_variant()`.

For PCV-based analyses, `select_pcil_families_by_variant()` should be run before `select_pcil_positive()` to restrict the search to families expected to segregate for the target variant.

Conceptually:

```text
                       Genomic target
                            │
              ┌─────────────┼─────────────┐
              │             │             │
             Gene         Region       Position
              │             │             │
              └─────────────┼─────────────┘
                            ↓
                  select_pcil_positive()
                            ↓
                       PCIL (+)
```
